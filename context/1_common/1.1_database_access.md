# 1.1 データベースアクセス

> **重要：データベースアクセス手法の使い分け**  
> 基本は UniversalDAO を使用し、特定の条件下でのみ JDBCラッパー を使用してください。

### 基本方針（UniversalDAO推奨）
- **UniversalDAO**(推奨): JPAアノテーション + O/Rマッパー
- **JDBCラッパー**: 以下の場合のみ使用
  - UniversalDAOで対応できない機能が必要（スキーマ置換など）
  - バッチ処理でDatabaseRecordReaderを使用する場合
  - 特別な制御・最適化が必要な場合
- **テスト対応**: DaoContext(スタブ化), DaoFactory(各自実装が必要)(インスタンス生成)

## 基本CRUD
### Entity
```java
@Entity @Table(name = "USERS") public class User {
    @Id @Column(name = "USER_ID") private Long userId; // 自動採番項目（insert後は空のまま）
    @Column(name = "USER_NAME") private String userName;
    @Column(name = "EMAIL") private String email; // ユニーク項目
}
```

### CRUD操作
```java
UniversalDao.insert(user);                         // 登録
UniversalDao.findById(User.class, id);             // 検索(例外)
UniversalDao.findByIdOrNull(User.class, id);       // 検索(null)
UniversalDao.update(user); UniversalDao.delete(user);
```

### バージョン番号の自動設定

> **重要：**  
> Insert時UniversalDaoはバージョン番号を自動的に0に設定します。手動設定値は上書きされます。

### insert後の自動採番項目取得

> **重要：**  
> insertメソッドは自動採番項目を返しません。

#### ❌間違ったパターン
```java
// 自動採番項目が空のままになる
universalDao.insert(user);
return BeanUtil.createAndCopy(UserCreateResponseDto.class, user); // userIdが空
```

#### ✅正しいパターン
```java
universalDao.insert(user);
// ユニーク項目で再取得して自動採番IDを取得
User savedUser = universalDao.findBySqlFile(User.class, "FIND_BY_EMAIL", user);
return BeanUtil.createAndCopy(UserCreateResponseDto.class, savedUser);
```

### テスト対応Service
```java
public class UserService {
    private final DaoContext universalDao;
    public UserService() { this(DaoFactory.create()); }
    UserService(DaoContext universalDao) { this.universalDao = universalDao; }
    public User findById(Long id) { return universalDao.findById(User.class, id); }
}
```

```java
public class DaoFactory {
    private static final String DAO_CONTEXT_FACTORY = "daoContextFactory";
    private DaoFactory() {}
    public static DaoContext create() {
        final DaoContextFactory factory = SystemRepository.get(DAO_CONTEXT_FACTORY);
        return factory != null ? factory.create() : new BasicDaoContextFactory().create();
    }
}
```

## 可変条件の仕組み

> **重要：可変条件の変換ルール**  
> `$if(property) {SQL条件}`の変換ルール：
> - **入力あり**: `(0 = 1 or (SQL条件))` → 条件評価される
> - **入力なし**: `(0 = 0 or (SQL条件))` → 条件評価されない  
> - **配列/Collection**: null・サイズ0で除外
> 
> **重要**: ANDやORの接続詞は条件分岐不要

### ✅正しいSQL記述
```sql
SEARCH_USERS =
SELECT USER_ID, USER_NAME, EMAIL FROM USERS
WHERE $if (userName) {USER_NAME LIKE :userName%}
  AND $if (email) {EMAIL = :email}
ORDER BY USER_ID
```

### ❌間違ったSQL記述
```sql
WHERE $if (userName) {USER_NAME LIKE :userName%}
  $if (userName && email) {AND}  -- 不要
  $if (email) {EMAIL = :email}
```

## 動的SQL構文
- **可変条件**: `$if(property) {SQL条件}`
- **パラメータ**: `:propertyName`
- **LIKE**: `:userName%`(前方), `%:userName%`(部分)
- **IN句**: `(:userTypes[])`
- **ORDER BY**: `$sort(sortId) { (id_asc ID ASC) (default ID) }`

## JDBCラッパー（特定用途のみ）

### JDBCラッパーの使用条件

> **重要：**  
> JDBCラッパーは以下の場合にのみ使用してください。UniversalDAOで対応できる場合は使用しないこと。

- UniversalDAOで対応できない機能（スキーマ置換、特殊なSQL）
- バッチ処理のDatabaseRecordReaderでの読み取り
- パフォーマンス要件などで特別な制御が必要

### バッチ処理でのDatabaseRecordReader
```java
@Override
public DataReader<SqlRow> createReader(ExecutionContext context) {
    DatabaseRecordReader reader = new DatabaseRecordReader();
    
    // DbAccessSupportのgetSqlPStatementメソッドを使用
    SqlPStatement statement = getSqlPStatement("FIND_DATA");
    
    // パラメータ設定
    statement.setString(1, "ACTIVE");
    statement.setDate(2, BusinessDateUtil.getDate());
    
    reader.setStatement(statement);
    return reader;
}
```

### SQLファイル配置ルール
**`getSqlPStatement("SQLID")`使用時のSQLファイル配置:**

```
Actionクラス: com.example.batch.UserBatchAction
SQLファイル: src/main/resources/com/example/batch/UserBatchAction.sql
```

**SQLファイル内容例:**
```sql
FIND_DATA =
SELECT USER_ID, USER_NAME, STATUS 
FROM USERS 
WHERE STATUS = ?
  AND CREATED_DATE >= ?
ORDER BY USER_ID

UPDATE_STATUS =
UPDATE USERS 
SET STATUS = ?, UPDATED_DATE = ?
WHERE USER_ID = ?
```

### 注意事項
- **SQLファイル取得**: バッチActionでは`getSqlPStatement("SQLID")`を使用
- **SQLファイル配置**: ActionクラスのパッケージパスでSQLファイルを自動特定
- **SQLインジェクション対策**: 必ずPreparedStatementを使用
- **可変条件**: `$if(property) {条件}` 構文はJDBCラッパーでも使用可能
- **テスト**: JDBCラッパー使用部分は別途テスト設計が必要
