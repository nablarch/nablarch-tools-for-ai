# Nablarch データベースアクセス実装ガイド

## アクセス手法
- **UniversalDAO**(推奨): JPAアノテーション + O/Rマッパー
- **JDBCラッパー**: 直接SQL実行
- **テスト対応**: DaoContext(スタブ化), DaoFactory(インスタンス生成)

## 基本CRUD
### Entity
```java
@Entity @Table(name = "USERS") public class User {
    @Id @Column(name = "USER_ID") private Long userId; // 自動採番項目（insert後は空のまま）
    @Column(name = "USER_NAME") private String userName;
    @Column(name = "EMAIL") private String email; // ユニーク項目
}
```

### CRUD操作
```java
UniversalDao.insert(user);                         // 登録
UniversalDao.findById(User.class, id);             // 検索(例外)
UniversalDao.findByIdOrNull(User.class, id);       // 検索(null)
UniversalDao.update(user); UniversalDao.delete(user);
```

### 🔴重要：バージョン番号の自動設定
**UniversalDaoはバージョン番号を自動的に0に設定します。手動設定値は上書きされます。**

### 🔴重要：insert後の自動採番項目取得
**insertメソッドは自動採番項目を返しません。**

#### ❌間違ったパターン
```java
// 自動採番項目が空のままになる
universalDao.insert(user);
return BeanUtil.createAndCopy(UserCreateResponseDto.class, user); // userIdが空
```

#### ✅正しいパターン
```java
universalDao.insert(user);
// ユニーク項目で再取得して自動採番IDを取得
User savedUser = universalDao.findBySqlFile(User.class, "FIND_BY_EMAIL", user);
return BeanUtil.createAndCopy(UserCreateResponseDto.class, savedUser);
```

### テスト対応Service
```java
public class UserService {
    private final DaoContext universalDao;
    public UserService() { this(DaoFactory.create()); }
    UserService(DaoContext universalDao) { this.universalDao = universalDao; }
    public User findById(Long id) { return universalDao.findById(User.class, id); }
}
```

## SQLファイル検索
**配置**: `com.example.entity.User` → `com/example/entity/User.sql`

### 実装パターン
```java
// 検索条件Bean
public class UserSearchDto { private String userName, email; }

// SQL実行
UniversalDao.findAllBySqlFile(User.class, "SEARCH_USERS", form);
long count = UniversalDao.countBySqlFile(User.class, "SEARCH_USERS", form); // 件数取得(COUNT用SQL不要)
```

## 🔴重要：可変条件の仕組み
**`$if(property) {SQL条件}`変換ルール:**
- **入力あり**: `(0 = 1 or (SQL条件))` → 条件評価される
- **入力なし**: `(0 = 0 or (SQL条件))` → 条件評価されない  
- **配列/Collection**: null・サイズ0で除外

**重要: ANDやORの接続詞は条件分岐不要**

### ✅正しいSQL記述
```sql
SEARCH_USERS =
SELECT USER_ID, USER_NAME, EMAIL FROM USERS
WHERE $if (userName) {USER_NAME LIKE :userName%}
  AND $if (email) {EMAIL = :email}
ORDER BY USER_ID
```

### ❌間違ったSQL記述
```sql
WHERE $if (userName) {USER_NAME LIKE :userName%}
  $if (userName && email) {AND}  -- 不要
  $if (email) {EMAIL = :email}
```

## 動的SQL構文
- **可変条件**: `$if(property) {SQL条件}`
- **パラメータ**: `:propertyName`
- **LIKE**: `:userName%`(前方), `%:userName%`(部分)
- **IN句**: `(:userTypes[])`
- **ORDER BY**: `$sort(sortId) { (id_asc ID ASC) (default ID) }`

## 高度な機能
```java
// バッチ実行
UniversalDao.batchInsert(users); batchUpdate(users); batchDelete(users);

// ページング
EntityList<User> users = UniversalDao.per(size).page(page).findAllBySqlFile(...);
users.getPagination().getResultCount(); // 件数, getPageCount(); // ページ数

// 遅延ロード(大量データ)
try (DeferredEntityList<User> users = UniversalDao.defer().findAllBySqlFile(...)) {
    for (User user : users) { /* 1件ずつ処理 */ }
}
```
