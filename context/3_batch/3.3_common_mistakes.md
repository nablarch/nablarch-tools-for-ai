## 5. N+1問題

```java

    return new Success();

// ✅ JOIN使用
@Override

```

@Override
public Result handle(SqlRow record, ExecutionContext context) {
    ProjectDto dto = EntityUtil.createEntity(ProjectDto.class, record);
    mapper.write(dto); // フレームワークがCSV生成
    return new Success();
}

@Override
protected void terminate(Result result, ExecutionContext context) {
    this.mapper.close(); // リソース解放
}
```

**修正ポイント**:
- `initialize()` でファイルオープン
- `ObjectMapper` でCSV出力
- `terminate()` でリソース解放

## 5. 業務日付取得の問題

### ❌ 間違った実装: システム日付を直接使用

```java
// システム日付を使用（業務日付ではない）
Date currentDate = new Date();
String dateStr = new SimpleDateFormat("yyyy-MM-dd").format(currentDate);
```

### ✅ 正しい実装: BusinessDateUtilを使用

```java
// 業務日付を使用
String businessDate = BusinessDateUtil.getDate();
Date bizDate = new Date(DateUtil.getDate(businessDate).getTime());
```

**修正ポイント**:
- `BusinessDateUtil.getDate()` で業務日付を取得
- 業務運用に合わせた日付を使用

## 6. データ変換の問題

### ❌ 間違った実装: 手動変換

```java
// 手動でDTOに詰め替え（漏れやミスのリスク）
ProjectDto dto = new ProjectDto();
dto.setProjectId(record.getString("PROJECT_ID"));
dto.setProjectName(record.getString("PROJECT_NAME"));
dto.setStartDate(record.getString("START_DATE"));
// 項目が多いと漏れやすい
```

### ✅ 正しい実装: EntityUtilを使用

```java
// フレームワークが自動変換
ProjectDto dto = EntityUtil.createEntity(ProjectDto.class, record);
// 必要に応じて追加設定のみ
dto.setProcessedDate(BusinessDateUtil.getDate());
```
