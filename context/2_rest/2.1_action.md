# 2.1. Action（リソースクラス）実装

NablarchでのREST API実装パターン。JAX-RSアノテーション使用。

> **重要：レスポンス実装の注意点**
> 
> - **レスポンスボディ + ステータスコード指定（200以外）** → **必ずEntityResponseを使用**
> - レスポンスボディのみ（200固定）→ エンティティを直接return
> - ステータスコードのみ（ボディなし）→ HttpResponseを使用

> **注意：Nablarchで使用可能なJAX-RSアノテーション**
> 
> Nablarchでは標準的なJAX-RSアノテーションのうち、以下のもののみがサポートされています：
> - `@Path`、`@GET`、`@POST`、`@PUT`、`@PATCH`、`@DELETE`
> - `@Produces`、`@Consumes`、`@Valid`
> 
> **使用できないJAX-RSアノテーション：**
> - `@BeanParam`、`@QueryParam`、`@PathParam`、`@FormParam`
> - `@Context`、`@HeaderParam`、`@CookieParam` など
> 
> パラメータ取得は `JaxRsHttpRequest` を使用してください。

## 基本実装
```java
@Path("/api/users")
public class UserAction {
    
    @GET
    @Produces(MediaType.APPLICATION_JSON)
    public List<User> findAll() {
        UserService userService = new UserService();
        return userService.findAll(User.class); // ハンドラにて自動的にJSON変換される
    }

    @GET
    @Produces(MediaType.APPLICATION_JSON)
    public List<UserDto> find(JaxRsHttpRequest request) {
        UserService userService = new UserService();
        // ★Nablarchでは@QueryParam、@BeanParamは使用不可
        // クエリパラメータはJaxRsHttpRequest.getParamMap()で取得
        UserSearchForm form = BeanUtil.createAndCopy(UserSearchForm.class, request.getParamMap());
        ValidatorUtil.validate(form);
        UserSearchCondition condition = BeanUtil.createAndCopy(UserSearchCondition.class, form);
        return userService.findUsers(condition);
    }
    
    @POST
    @Valid
    @Consumes(MediaType.APPLICATION_JSON)
    @Produces(MediaType.APPLICATION_JSON)
    public HttpResponse create(UserForm form) {
        UserService userService = new UserService();
        // ★@Valid + @Consumesでリクエストボディが自動的にUserFormに変換される
        User user = BeanUtil.createAndCopy(User.class, form);
        User created = userService.create(user);
        // ★レスポンスボディを持ちかつステータスコードを設定したい場合は必ずEntityResponseを使用
        return new EntityResponse<User>()
                .setEntity(created)
                .setStatusCode(HttpResponse.Status.CREATED.getStatusCode());
    }
    
    @GET
    @Path("/{id}")
    @Produces(MediaType.APPLICATION_JSON)
    public User get(JaxRsHttpRequest request) {
        UserService userService = new UserService();
        // ★Nablarchでは@PathParamは使用不可
        // パスパラメータはJaxRsHttpRequest.getPathParam("名前")で取得
        Long id = Long.valueOf(request.getPathParam("id"));
        return userService.findById(id);
    }
    
    @PATCH
    @Path("/{id}")
    @Valid
    @Consumes(MediaType.APPLICATION_JSON)
    public HttpResponse update(UserForm form, JaxRsHttpRequest request) {
        UserService userService = new UserService();
        // ★リクエストボディ（UserForm）は@Valid + @Consumesで自動変換
        // ★パスパラメータ（id）はJaxRsHttpRequestから手動取得
        Long id = Long.valueOf(request.getPathParam("id"));

        User existingUser = userService.findById(User.class, id);

        // Formの値で既存データを更新
        // @Valid + @Consumesでバリデーション済Formが引数に渡ってくる
        BeanUtil.copy(form, existingUser);
        userService.update(existingUser);

        return new HttpResponse(HttpResponse.Status.NO_CONTENT.getStatusCode());
    }
    
    @DELETE
    @Path("/{id}")
    public HttpResponse delete(JaxRsHttpRequest request) {
        UserService userService = new UserService();
        Long id = Long.valueOf(request.getPathParam("id"));

        userService.delete(id);

        return new HttpResponse(HttpResponse.Status.NO_CONTENT.getStatusCode());
    }
}
```

## アノテーション

### Nablarchで使用可能なJAX-RSアノテーション

#### URL・HTTPメソッド
- `@Path("/api/users")`：クラス・メソッドレベルでURLマッピング
- `@GET` `@POST` `@PATCH` `@PUT` `@DELETE`：HTTPメソッド
- `@Produces(MediaType.APPLICATION_JSON)`：レスポンス形式
- `@Consumes(MediaType.APPLICATION_JSON)`：リクエスト形式
- `@Valid`：リクエストボディの自動バリデーション

### パラメータ取得方法

#### リクエストボディの取得
`@Valid` + `@Consumes`で**自動変換**が可能：

```java
@POST
@Valid
@Consumes(MediaType.APPLICATION_JSON)
public HttpResponse create(UserForm form) {
    // リクエストボディが自動的にUserFormに変換される
    // ...
}
```

#### クエリパラメータ・パスパラメータの取得
JAX-RSの `@QueryParam`、`@PathParam`、`@BeanParam` などは**使用できません**。
`JaxRsHttpRequest`を使用して手動取得：

#### ✅ 正しい実装パターン
```java
@GET
public List<UserDto> find(JaxRsHttpRequest request) {
    // クエリパラメータをJaxRsHttpRequestから取得
    UserSearchForm form = BeanUtil.createAndCopy(UserSearchForm.class, request.getParamMap());
    ValidatorUtil.validate(form);
    // ...
}

@GET
@Path("/{id}")
public User get(JaxRsHttpRequest request) {
    // パスパラメータもJaxRsHttpRequestから取得
    Long id = Long.valueOf(req.getPathParam("id"));
    // ...
}
```

#### ❌ 使用できない実装パターン
```java
// これらのアノテーションはNablarchでは使用できません
@GET
public List<UserDto> find(@BeanParam UserSearchForm form) { // NG
    // ...
}

@GET
public List<UserDto> find(@QueryParam("name") String name) { // NG
    // ...
}

@GET
@Path("/{id}")
public User get(@PathParam("id") String id) { // NG
    // ...
}
```

## レスポンス実装パターン

### HttpResponseとEntityResponseの使い分け

#### レスポンスボディなし（204 No Content、404 Not Found等）
```java
@DELETE
@Path("/{id}")
public HttpResponse delete(JaxRsHttpRequest request) {
    // ボディがない場合はHttpResponseを使用
    return new HttpResponse(HttpResponse.Status.NO_CONTENT.getStatusCode());
}
```

#### **レスポンスボディあり + ステータスコード指定（200以外） → 必ずEntityResponseを使用**
```java
@POST
@Valid
@Consumes(MediaType.APPLICATION_JSON)
@Produces(MediaType.APPLICATION_JSON)
public HttpResponse create(UserForm form) {
    User created = userService.create(user);
    
    // ★重要：201 Createdなど200以外のステータスコードを設定する場合は
    // 必ずEntityResponseを使用すること（エンティティ直接returnでは200になってしまう）
    return new EntityResponse<User>()
            .setEntity(created)
            .setStatusCode(HttpResponse.Status.CREATED.getStatusCode()); // 201
}
```

#### レスポンスボディのみ（ステータスコード200固定）
```java
@GET
@Produces(MediaType.APPLICATION_JSON)
public List<User> findAll() {
    // ステータスコード200で良い場合はエンティティを直接返せる
    return userService.findAll();
}
```

### EntityResponse使用時の注意点
- **必須**：`.setEntity()`でレスポンスボディを設定
- **必須**：`.setStatusCode()`でHTTPステータスコードを設定
- メソッドの戻り値型は`HttpResponse`とする（`EntityResponse<T>`ではない）
